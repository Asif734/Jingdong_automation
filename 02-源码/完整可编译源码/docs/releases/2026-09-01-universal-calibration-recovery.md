# 通用自适应校准恢复版发布说明

## 解决的问题

- 同事 B 的千牛 AX 树暴露 40 个可按控件时，旧算法把它们全部当作发送按钮，导致兼容 profile 被拒绝、OCR/V2 不预热、程序无法运行。
- 首次安装继承旧配置中的 `autoStartWhenReady=false`，导致自检完成后仍不会自动开始。
- 诊断包没有记录“为什么选择发送控件或为什么降级”，另一台电脑上的 Codex 只能猜测。
- 旧开发交付依赖隐藏 `.git` 目录，微信/ZIP 传输后经常丢失，接手电脑无法可信修改源码。

## 当前行为

- 发送控件使用语义和布局评分；唯一可靠候选使用控件动作。
- 不能唯一确认时自动降级为一次 Return，标记 fallback 并继续预热/运行。
- 首次安装保留客服名称、聊天历史和图片指纹，同时默认启用“准备好后自动开始”；用户后续关闭会被尊重。
- 诊断包新增 `calibration-diagnostics.json`，UI 明确区分 verified、fallback 和 unavailable。
- 完整开发交付使用 Git bundle 保存全部提交/分支/标签，并通过真实克隆和 HEAD 比对后才打包。

## 发布边界

自动化测试和 A/B fixture 不能替代真机验收。发布时应准确表述为“结构兼容回放及本机构建通过”；只有同事机器实际达到 `endToEndVerified` 后，才能说该机完整文字链路通过。
