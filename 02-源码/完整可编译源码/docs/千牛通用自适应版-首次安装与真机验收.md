# 千牛通用自适应版：首次安装与真机验收

## 先分清两个“就绪”

- `readOnlyReady`（只读检查已就绪）：权限、接待中心、客服名称、专用 Codex、页面校准、OCR 和 V2 均已通过，但还没有证明这台电脑能真实发出消息。
- `endToEndVerified`（完整链路已验证）：至少一条授权测试消息已经完成“红点 → 打开客户 → OCR → V2 → Codex → 输入 → 发送 → 发送后确认”。

看到 `readOnlyReady` 不能直接宣称所有电脑都已经跑通；完成文字真机测试后才能升级为 `endToEndVerified`。

## 一键安装

1. 先退出所有旧自动客服，确认活动监视器里没有其他 `AutoReplyApp`。千牛本身可以保持登录。
2. 打开 `千牛全自动客服-通用自适应版.dmg`。
3. 双击唯一的 `安装并启动.app`，再点一次“安装并启动”。
4. 安装器先校验每个文件、arm64 架构和签名，再安装到：
   - 首选：`/Applications/千牛全自动客服-通用自适应版.app`
   - 无系统目录写权限时：`~/Applications/千牛全自动客服-通用自适应版.app`
5. 若已有同名版，安装器先改名保留；新版本安装后复验失败会自动恢复旧版。安装器只会从固定安装路径启动，不会从 DMG 或临时目录运行。
6. 内部 ad-hoc 包首次打开可能被 Gatekeeper 拦截：到“系统设置 → 隐私与安全性”选择仍要打开。只有构建日志显示 `NOTARIZATION_ACCEPTED=1` 才是正式公证包。

## 第一次自动配置

按 App 内八步向导依次完成：

1. 辅助功能：给“千牛全自动客服-通用自适应版”授权。
2. 屏幕录制：给同一个新 Bundle 授权；旧版权限不会自动转移。
3. 千牛：登录卖家账号、保持在线、打开客服接待中心。
4. 千牛会话模式：选择文本模式，接待中心窗口保持可见；不要打开多个自动客服。
5. 客服名称：填写这台电脑实际显示的一个或多个客服名，逗号分隔。
6. Codex：程序会优先安全继承本机已登录的 Codex 账号，只复制登录缓存，不复制个人 Skill、AGENTS、规则或配置；无法继承时再点“授权本机 Codex 账号”完成一次设备授权。
7. 自动校准：程序读取本机 macOS、千牛、窗口、显示器、AX 行和控件结构，为这台电脑生成独立 profile；不会把同事 B 的坐标硬套到同事 A。
8. 预热：OCR、V2 常驻检索 worker 和 Codex 就绪探针全部结束后，界面显示“只读自检已完成”。

校准 profile 会按环境指纹复用。千牛版本、窗口结构或显示器拓扑改变时，只重校受影响能力；候选校准失败会回滚 last-known-good，不会覆盖可用 profile。

## 真机文字验收

只使用已授权测试买家账号：

1. 自动回复先保持停止，确认 UI 为 `readOnlyReady`。
2. 开启自动回复，买家发送一条可核对答案的普通文字，例如某型号是否支持 Wi‑Fi。
3. 记录时间：客户发出、发现红点、OCR 完成、V2 完成、Codex 完成、发送完成。
4. 验收：正确客户、回答与资料一致、输入框清空或出现新客服气泡、没有重复发送。
5. 只有发送后证据成立才记录 `endToEndVerified`。发送结果不确定不能冒充通过。

## 真机图片验收

1. 买家发送一张新的、从未发过的测试图片。
2. 检查图片被复制一次、剪贴板确实变为图片、图片进入冻结的本轮上下文。
3. 检查同一图片没有被无限复制或重复提交；10 秒媒体边界后必须释放 UI，让其他任务继续。
4. 记录是否 PASS。图片失败不能掩盖为通用通过；可以标为“图片能力降级”，前提是文字链路独立正常。

## 真机视频占位验收

本版只识别并忽略客户视频，尚未把视频提交给另一个账号：

1. 买家发送一段新的测试视频。
2. 程序先由视觉确认聊天区存在媒体块，再读取千牛增量日志。
3. 只有同一个 `messageId` 明确出现 `messageType=105` 才按视频处理；视频不得触发图片复制、下载、删除、AI 或客服回复。
4. 本地只保存不可逆的事件摘要作为判重，不保存视频或整行日志；同一个视频重试或重启后仍保持忽略。
5. `messageType=101` 继续原图片流程；日志缺失、冲突或无法精确匹配时也继续按图片处理，不能因为辅助日志失效丢失客户图片。
6. 图片和文字连续发送时，文字仍正常回答；新事件会阻止旧视频记录误吞后来的图片。

当前“视频接口”只是未来转交其他账号的扩展点。验收看到“视频已忽略”属于预期，不代表视频转交已经实现。

## 导出证据给 Codex

在“高级能力详情”点击“导出脱敏诊断包”。默认包包含：

- 环境指纹和相对窗口结构；
- 本机 capability/profile；
- `readiness-state.json`（只读就绪和完整链路验证分开）；
- 最多 200 条脱敏结构化错误。

默认不含客户 UID、昵称、完整聊天、登录凭证、个人 Codex 配置和全屏原图。只有操作者本次明确勾选“包含原始证据”才会附加原始文件。

## 回滚与停止

1. 在当前 App 点停止，等待 CLI/UI 操作释放后退出。
2. 不要同时启动版本 A、旧候选版和通用版。
3. 安装失败由安装器自动恢复；安装成功后需要手工回退时，先保存诊断，再把 Applications 中的当前 App 移走，并恢复最近的 `.backup-时间戳`。
4. 不要手工合并不同版本的调度队列、回答游标或聊天数据，否则可能重复回复。
