# 千牛可靠性正式接入设计

## 范围

把已经通过隔离实验的三个能力接入现有千牛自动客服：运行意图恢复、发送不确定自动对账、跨 Mac 运行资源解析。保留现有 OCR、红点检测、客户身份判断、FIFO、Prompt、模型、V2 Top-12 检索排序与详细日志。问题 8 的日志清理不在本次范围内。

## 运行意图恢复

在 `运行状态/运行意图.json` 原子保存用户明确选择的 `running`/`stopped`、全部客户/测试模式及客服名称。用户点击开始时先保存运行意图，再尝试启动；瞬时环境错误不得把运行意图改为停止，而是按 1、2、5、10、30 秒封顶重试。用户点击停止时先保存停止意图并取消重试。应用重新打开时，若持久化意图为运行，则恢复模式和客服名称并自动进入相同的启动重试流程。

本次只实现“应用进程重新打开后自动恢复”，不注册系统 LaunchAgent，不改变 macOS 登录项或后台守护策略。

## 发送不确定自动对账

发送结果不确定后，记录保持在 `uncertain`，但不再永久隔离。调度器在没有更高优先级的已就绪发送时，对该 UID 做只读 OCR 对账：

- 历史中出现与冻结回复完全一致的客服消息，确认发送成功并推进 answered cursor。
- OCR、窗口、身份或历史不可用时仅等待，不累计“未发现”。
- 连续三次成功读取且未发现原回复，补发原始回复一次。
- 补发后仍连续三次成功读取且未发现，记录以 `completed + uncertain` 终结，推进该冻结批次的 operational cursor 并释放 UID；不再生成或重复发送旧批次。

对账复用现有 `captureBeforeDelivery` 身份核对和 OCR，不新增坐标点击算法。每次补发仍走现有发送事务的发送前/发送后 UID 核对。

## 可移植运行资源

运行时不再依赖固定 `/Users/scy` 或系统 Python：

- Python、V2 脚本、site-packages 和模型缓存从 App bundle 相对路径解析。
- 构建阶段将 Python framework、V2 资源及知识库种子打入 App。
- 首次运行把知识库种子复制到用户 Application Support；后续从该稳定位置读取。
- Codex 从有序候选位置选择，至少支持 ChatGPT App 内置 Codex。
- 缺少任何必需组件时开始按钮明确阻断并显示缺项。
- V2 检索失败时不得静默退回把完整 ZIP 交给模型。

## 持久化兼容

调度器记录新增的对账字段使用可选字段和解码默认值，现有 schema 3 检查点必须继续读取。既有 `sending` 记录恢复为可对账的 `uncertain`。日志格式继续追加，不清理、不轮转。

## 验收

- 运行意图在模型重建后恢复；明确停止后不会自行重启。
- 瞬时启动检查失败不丢失运行意图，退避封顶为 30 秒。
- 不确定发送最多补发一次，最终一定释放该 UID。
- 不可读观察不会导致补发。
- 旧调度器状态仍可读取。
- 运行路径不包含固定用户名；缺少 Python、知识库或 Codex 时明确阻断。
- 完整 Swift 测试、V2 Python 测试和打包验证通过。
- 不删除或轮转任何生产日志。
