# 格志客服模型测试器设计

## 目标

制作一个可分享给同事的独立 macOS 应用，只测试当前格志客服模型本身。应用不得连接千牛、读取未读红点、执行 OCR 或自动发送消息。

## 固定行为

- 模型固定为 `gpt-5.6-sol`。
- 推理强度固定为 `medium`。
- 复用现有 `PromptBuilder`、`CodexReplyGenerator` 与 V2 Top-12 知识库检索，不另写一套回答算法。
- 知识库随应用分发，用户不需要选择桌面文件。
- 不包含 API Key、Codex token 或任何开发者账号凭据。
- 每位同事使用自己电脑上的 Codex，并通过自己的 ChatGPT 账号登录。
- 如果固定模型不可用，明确报错；不得自动切换模型。

## 目标平台

- 第一版支持 Apple Silicon Mac（M1/M2/M3/M4）。
- 最低 macOS 14。
- 正式分享物为 `格志客服模型测试器.dmg`。

## 应用结构

新建独立 Swift Package：`components/model-tester-source`。它依赖现有 `components/batch-source`，只调用回答生成与知识检索接口，不依赖 OCR、发送器、未读助手或自动回复调度器。

应用包包含：

- 清洗后的知识库 ZIP；
- V2 检索脚本、Python依赖和本地向量模型缓存；
- 回复 JSON Schema；
- 应用与知识库版本清单。

知识库和种子缓存位于只读 App Resources。运行时缓存、会话绑定和测试记录写入 `~/Library/Application Support/GrozziieModelTester/`。

## Codex 发现与登录

按以下顺序寻找 Codex：

1. `/Applications/ChatGPT.app/Contents/Resources/codex`；
2. `/opt/homebrew/bin/codex`；
3. `/usr/local/bin/codex`；
4. 登录 shell 的 `PATH` 中的 `codex`。

启动时执行只读状态检查。若未登录，界面显示“登录 Codex”，点击后启动 `codex login` 的系统终端/浏览器流程。应用不得读取、复制或导出 `~/.codex/auth.json`。

## 测试会话

- “新建测试”创建唯一的本地测试 UID，并获得独立 Codex 会话。
- 同一测试窗口内连续追问时沿用该会话，保持上下文。
- 用户输入被序列化成与生产链路一致的 customer JSONL。
- 模型回复被追加为 service JSONL，作为下一次追问的真实历史。
- 支持把客户图片拖入输入区；图片作为当前 customer 消息的附件提交。
- 不允许模型或应用修改知识库和应用源文件。

## 界面

单窗口、三部分：

1. 顶部状态栏：Codex登录状态、固定模型/推理强度、知识库版本、设置入口。
2. 中部对话区：客户消息与客服回答气泡；支持复制回答。
3. 底部输入区：文本输入、图片附件、发送测试、新建测试。

底部折叠诊断栏显示：

- 总耗时、登录检查、Codex生成耗时；
- 新建/恢复会话状态；
- 提交历史字节数和图片数；
- 本次V2检索引用的资料文件；
- 明确的错误信息。

## 本地记录与导出

每次测试写入独立目录，包含 `history.jsonl`、`history.txt`、附件和 `run-metadata.json`。导出测试报告时生成一个不含凭据的 ZIP，包含完整对话、回答、引用资料、耗时、应用版本、Prompt版本、知识库哈希、模型和推理强度。

## 分发与安全

- 构建脚本只打包独立测试器需要的资源。
- 发布构建进行 Developer ID 签名、公证并生成 DMG；开发构建允许使用现有开发签名。
- 构建前校验知识库 SHA-256，避免误打包旧数据库。
- 日志和导出报告不得包含 Codex token、API Key 或其他凭据。
- 应用不申请辅助功能、屏幕录制或千牛控制权限。

## 验收标准

1. 应用在没有千牛运行时可独立完成多轮问答。
2. 运行记录证明模型为 `gpt-5.6-sol`、推理强度为 `medium`。
3. 应用使用随包知识库完成 V2 检索，能显示引用资料。
4. 未登录时不崩溃并给出明确登录入口；登录后无需 API Key。
5. 新建测试不继承前一测试的会话，连续追问保留当前测试上下文。
6. 应用包中不含凭据，也不依赖用户桌面的固定绝对路径。
7. 同事仅需安装应用并登录自己的 Codex，即可进行模型测试。
