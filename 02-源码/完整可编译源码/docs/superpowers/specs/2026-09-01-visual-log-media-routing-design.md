# 千牛视觉优先、日志精确区分图片/视频设计

日期：2026-09-01  
状态：用户已批准  
基线：通用自适应分支 `d5b2ae69350cf85fd3372cf518110ed6c61fa361`

## 目标

在不改变文字、图片、链接、OCR、V2、Codex 和发送主链路的前提下，增加一层媒体类型路由：视觉算法先判断聊天区是否出现媒体块；只有出现媒体块时才读取千牛增量日志，并用同一个 `messageId` 上的 `messageType` 判断图片或视频。

## 决策

- `messageType=101`：图片，继续原有“复制图片 → 判重 → 提交 AI → 回复”流程。
- `messageType=105`：视频，当前版本只记录“已识别并忽略”的占位事件；不复制、不下载、不删除、不提交 AI、不回复。
- `messageType=102`：文字，不参与媒体覆盖；文字仍完全由现有 OCR 聊天解析处理。
- 日志不存在、读取失败、类型冲突、找不到完全相同的 `messageId` 或没有足够新的同客户事件：返回 `unknown`，继续原图片流程，不能因辅助日志失效丢失客户图片。
- 日志只是一层精确分类辅助，不能代替视觉发现客户、红点、聊天内容或图片位置。

## 执行顺序

1. OCR 正常完成文字识别和视觉媒体候选检测。
2. 若没有媒体候选，完全不读取媒体日志，继续文字/链接流程。
3. 若有媒体候选，增量读取 `~/Library/Application Support/Aliworkbench/System/log/app.log` 与 `app.log.old`。
4. 从日志中分别提取客户新消息事件及 `messageType` 标记，并且只用完全相同的 `messageId` 合并。
5. 在当前客户 UID、事件时间窗口、尚未处理三个条件下选择最新事件。
6. 图片或未知：允许现有图片复制器运行。
7. 视频：在任何鼠标移动或复制点击前返回“忽略”，把 `messageId` 原子写入本地媒体日志游标并释放当前任务。

## 持久化与判重

文件位置：`运行状态/媒体路由/processed-events.json`。

只保存：

- `messageId` 的 SHA-256；
- 类型 `image`/`video`；
- 处理时间；
- 不可逆的客户 UID 摘要。

不保存原始聊天、客户昵称、图片、视频、登录信息或整行千牛日志。集合最多保留最近 10,000 项，原子覆盖，避免长期运行无限增长。

## 日志轮转

- 用设备号、inode 和偏移量识别文件延续、截断和轮转。
- 行未写完整时保留 remainder，看到换行后才解析。
- 第一次运行允许读取每个文件尾部最多 32 MiB，但只接受时间窗口内且与当前 UID 相同的事件。
- 运行中只读取新增字节，不重复扫描完整日志。

## 故障边界

- 媒体日志解析器异常：本次按图片处理，记录降级，不阻塞 OCR。
- 同一 `messageId` 同时出现 101 与 105：视为冲突，按图片处理，避免误吞客户图片。
- 视频只有红点、没有可解析正文：处理完成后不创建 AI 任务。
- 视频同时带文字：仅过滤视频媒体，文字仍进入原聊天历史并正常回答。
- 一个视频事件处理失败不能停止下一个客户、OCR 服务或调度器。

## 验收

1. 无媒体候选时，日志解析器调用次数为 0。
2. 视觉媒体 + 精确 101：图片复制器执行一次。
3. 视觉媒体 + 精确 105：图片复制器执行 0 次，AI 任务为 0。
4. 冲突、缺日志、错 UID、错 messageId：保留原图片路径。
5. 同一视频重启 App 后仍不会再次处理。
6. A/B/当前机兼容 fixture 与原有主程序、OCR、发送和批处理测试全部保持通过。
